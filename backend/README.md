# SInner — بک‌اند

API فروشگاه و تعمیرگاه سینر. لاراول ۱۲ روی PostgreSQL و Redis.

قرارداد اندپوینت‌ها از لایه‌ی mock فرانت گرفته شده (`front end/src/mocks/handlers.ts`)
و شکل پاسخ‌ها دقیقاً همان تایپ‌های `front end/src/types/*.ts` است.

## راه‌اندازی

```bash
docker compose up -d          # پستگرس روی ۵۴۳۳ و ردیس روی ۶۳۸۱
php composer.phar install
php artisan migrate --seed    # داده‌ی نمونه از database/seeders/data/*.json
php artisan serve --port=8000
```

پورت‌ها عمداً غیرپیش‌فرض‌اند تا با پستگرس و ردیسِ پروژه‌های دیگرِ همین دستگاه تداخل نکنند.

## وصل کردن فرانت

در `front end/.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
NEXT_PUBLIC_API_MOCKING=disabled
```

نبودن این فایل یعنی برگشت به داده‌ی ساختگی؛ هیچ کد دیگری عوض نمی‌شود.

## حساب‌های نمونه

رمز همه: `password`

| شماره | نقش |
|---|---|
| `09120000001` | مدیر کل |
| `09120000002` | ادمین کاتالوگ |
| `09121234567` | مشتری |

ورود با کد یک‌بارمصرف هم کار می‌کند؛ خارج از محیط production کد در پاسخ
`POST /api/v1/auth/otp/request` زیر کلید `devCode` برمی‌گردد تا بدون سرویس
پیامک هم بشود تست کرد. هر دو روش از پنل (تنظیمات ← روش‌های ورود) خاموش می‌شوند.

## چیزهایی که سرور تصمیم می‌گیرد، نه مرورگر

اینها عمداً از کلاینت پذیرفته نمی‌شوند:

- **قیمت و موجودی کالا** از مدل‌ها ساخته می‌شود: ارزان‌ترین مدل قیمتِ «از» و جمع
  موجودی‌ها موجودی کل (`Product::syncPricingFromVariants`).
- **مبلغ سفارش** از روی قیمت مدل‌ها دوباره حساب می‌شود و موجودی در همان تراکنش
  با `lockForUpdate` کم می‌شود.
- **کد تخفیف** با بازه‌ی اعتبار، سقف استفاده و فهرست کالاهای مجاز سنجیده می‌شود و
  مبلغش را سرور برمی‌گرداند.
- **دسترسی پنل** با میدل‌ور `permission:*` روی هر مسیر؛ چک سمت مرورگر فقط برای
  پنهان‌کردن منوهاست.

## نکته‌ی دیتابیس

`specs` کالا و اسناد محتوای سایت `jsonb`اند با ایندکس GIN — همیشه یکجا خوانده و
نوشته می‌شوند ولی روی همان‌ها فیلتر می‌شود. جست‌وجوی فارسی روی نام کالا از
`pg_trgm` استفاده می‌کند.
